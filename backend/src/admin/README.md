# Веб-панель продавца (расширение админки Medusa)

Панель оператора магазина — это расширяемая админка Medusa (`/app`), а не отдельное приложение:
`routes/` добавляют экраны, `widgets/` встраиваются в страницы ядра. Документация ядра —
[Admin Extensions](https://docs.medusajs.com/learn/fundamentals/admin).

## Как устроено

- `routes/<путь>/page.tsx` — экран + `defineRouteConfig({ label, icon })` (пункт сайдбара).
  `routes/settings/<путь>/page.tsx` — раздел на странице настроек.
- `widgets/*.tsx` — блоки внутри ядровых страниц (`defineWidgetConfig({ zone })`).
- `components/*.tsx` — по одному компоненту на файл (drawer'ы, промпты, карточки).
- `lib/*.ts` — DTO админ-API и карты статусов. Код бэкенда сюда НЕ импортируем: браузерный бандл
  не должен тянуть модули сервера, типы дублируются намеренно.
- `hooks/*.ts` — мутации и инвалидация кэша react-query.
- `i18n/` — переводы (`en` — канон, `ru`), см. `i18n/README.md`.
- `styles/` — слой бренда (ниже). `assets/fonts/` — TTF IBM Plex Sans.

## Оболочка: режим продавца и владельца (с T4.1a)

- **Роль** — `user.metadata.role`: `seller` — обычный продавец, отсутствие значения
  или `owner` — владелец (существующие учётки админа продолжают видеть всё).
  Учётку продавца создаёт `src/scripts/create-seller-user.ts`, читает роль
  `lib/shell-role.ts`.
- **Режим** ставит `lib/shell-mode.ts`: атрибут `data-sm-shell="seller|owner"` на
  `<html>` (первый кадр — из кэша localStorage, затем сверка с `/admin/users/me`)
  плюс открытие панели на «Дашборде» после входа вместо ядрового списка заказов.
- **Обрезка** — `styles/shell.css`: порядок пунктов сайдбара (всем ролям) и
  скрытие владельческих разделов (только продавцу): акции, прайс-листы,
  подпункты структуры каталога/клиентов, все настройки кроме «Профиля», а с
  T10.14e — ядровый «Склад» (`/app/inventory`): рабочее место склада у продавца
  — наш экран «Цены и остатки», а в ядровой таблице складских позиций нет даже
  названий товаров. У владельца пункт остаётся.
- **Подмена ядровых адресов** (с T4.14c) — чистое правило `lib/shell-redirect.ts`:
  корень `/app` ведёт на «Дашборд», ядровый список заказов `/app/orders` — на наш
  экран «Заказы» (`/app/order-queue`; пункт сайдбара скрыт ещё с T4.2b, но адрес
  жив — хлебная крошка страницы заказа, поиск ⌘K, закладка). Применяет правило
  `shell-mode.ts`: и при заходе по адресу, и на переходах внутри панели —
  перехватом `history.pushState/replaceState`. Уводим ПОЛНОЙ загрузкой: роутер
  ядра считает переход по своему аргументу, и подмена адреса на лету дала бы
  ядровый экран под нашим адресом. Вход по-прежнему заканчивается «Дашбордом» —
  правило различает переход СО страницы входа.
- **Ядровые действия перехода на странице заказа убраны** (T4.14c): «Выполнить
  заказ», «Отметить как отправленный», «Отметить как доставленный» — статус
  двигает только наш drawer (T4.2c), а расхождение, если операцию сделали мимо
  панели, догоняют подписчики (T4.14b). Область правил задаёт не разбор адреса,
  а React: виджет `widgets/order-page-mode.tsx` держит `data-sm-page="order"`,
  пока открыта страница. **Правила ограничены блоком выполнения** — его
  контейнеры лежат в своей обёртке `div.flex.flex-col.gap-y-3` без `w-full`, а
  карточки страницы и НАШИ виджеты — прямые дети колонки `w-full min-w-0`. Без
  этой рамки правило «…»-меню снимает меню и с наших карточек: контейнер
  `divide-y p-0` с «…» — общая идиома панели (поймано на стенде).
- **Технический мусор ядра убран** (T4.13) — `styles/core-noise.css`: карточки
  «Метаданные» и «JSON · N ключей» на ядровых страницах (заказ, товар,
  покупатель, складская позиция). Различаем их по разметке, не по тексту:
  «Метаданные» — единственная карточка со ссылкой `…/metadata/edit` прямым
  потомком, «JSON» — карточка-строка с заголовком-бейджем и кнопкой Drawer'а
  (`aria-haspopup="dialog"`). Данные на месте — скрыт вид, адрес
  `/app/orders/<id>/metadata/edit` открывается руками.
- **Подписи ядра, которых нет в i18n** (T4.13) — правило `lib/shell-text.ts`,
  применяет `shell-mode.ts` обходом текстовых узлов + `MutationObserver`. Часть
  надписей дашборд печатает строкой в коде: «Total pending», статусы платежа
  `Pending`/`Captured`, идентификаторы провайдеров (`pp_kaspi_kaspi`,
  `manual_manual`), «Add» в адресах покупателя, дата «02 Sep, 2026, 14:02:49».
  Подмена — по ТОЧНОМУ совпадению узла целиком и только в русской панели
  (в английской ядровая надпись и так на своём языке); дата пересчитывается в
  обеих — общим форматтером `lib/date.ts`. Тем же проходом снимаются строки
  «MID код» / «HS код» карточки товара (атрибут `data-sm-noise="row"`, прячет
  `core-noise.css`). Всё, что МОЖНО перевести ключом, переводится в
  `i18n/json/*` — сюда попадает только то, чего в i18n ядра нет.
- **Это не права доступа.** Admin-API ядра одинаково доступно всем
  admin-пользователям, скрытый адрес продавец может открыть руками. Слой даёт
  прод-ВИД панели; настоящее разграничение — открытая развилка №4
  (DECISIONS 2026-08-04).
- Подключение — одним импортом из `routes/dashboard/page.tsx` (расширения
  попадают в общий входной чанк, поэтому действует на всей панели, включая
  ядровые экраны). Селекторы опираются на разметку ядра — при обновлении Medusa
  проверять файл; при расхождении слой просто перестаёт действовать.

## Даты и локаль

- Локаль вне React (сайдбар, модульные форматтеры) — `lib/locale.ts` (cookie
  `lng` → localStorage, как детектор i18next). Смена языка применяется после
  перезагрузки страницы.
- Даты — ТОЛЬКО `lib/date.ts` (`formatDate`, `formatDateTime`, `formatDayMonth`).
- Номера телефонов — ТОЛЬКО `lib/phone.ts` (`formatPhone` — вид для человека, `phoneSearchTerm` —
  приведение строки поиска к канону `+7XXXXXXXXXX`). На экране номер всегда разбит на группы, в
  базе лежит каноном: экран, который показывает одно, а ищет по другому, не находит номер, который
  сам же и напечатал (поймано в T5.1a).
  Свой `toLocaleDateString` в экране — регресс: до T4.1a восемь экранов были
  зашиты на `en-US`, два — на `ru-RU`, и русская панель показывала
  «Jul 15, 2026» рядом с «15 июл. 2026 г.».

## Дизайн-система панели (с T4.1)

- **Токены** — `styles/brand.css`. Файл переопределяет семантические переменные `@medusajs/ui-preset`
  (`--fg-*`, `--bg-*`, `--border-*`, `--button-*`, `--tag-*`) брендовыми значениями, поэтому
  ядровые экраны и наши экраны на классах `text-ui-fg-base` / `bg-ui-bg-subtle` рисуют бренд без
  правки разметки. Свет — `html:root`, тьма — `html.dark:root`: берём **специфичностью**, потому
  что ядровый CSS попадает в бандл позже нашего.
- Подключается **одним импортом** из `routes/dashboard/page.tsx`. Расширения собираются в общий
  бандл админки, поэтому стиль действует на всю панель. Второй раз импортировать не нужно.
- **Произвольные утилиты Tailwind не работают.** Дашборд поставляется собранным CSS: доступны
  только классы, которые ядро само использует. Всё, чего там нет (сетки `grid-cols-4`,
  произвольные значения `text-[30px]`), задаём своими классами `sm-*` — пример
  `styles/dashboard.css`. Внутри них цвета — ТОЛЬКО `var(--sm-*)`, ad-hoc значений нет.
- **Шрифт** — IBM Plex Sans, те же TTF, что в `mobile/packages/ui_kit` и на витрине; `@font-face`
  в `brand.css`, отдельное правило перекрывает утилиту `.font-sans` дашборда.
- **Что бренд НЕ трогает (T4.17, приёмка владельца 2026-08-18):** заливку кнопок ядра
  (`--button-inverted*` НЕ переопределяем — primary остаётся #27272A: ядро рисует кнопку заливкой
  ПЛЮС своими `shadow-buttons-inverted` и градиентом `:after` с зашитыми значениями, и любая
  брендовая заливка под ними читается как чужой элемент) и иконки набора `@medusajs/icons`. Акцент
  бренда — на ссылках, чипах, бейджах, контролах и фокусе. Контрастные поверхности (`--contrast-*`,
  они же заливка primary) в ТЁМНОЙ теме тоже тёмные — как у ядра; объявления на `html:root`
  считаются от `--sm-ink`, а он в тёмной теме светлый, поэтому в `html.dark:root` их пересчитываем
  от поверхностей.
- **Иконка НАШЕГО пункта сайдбара** — только контурная (15×15, `strokeWidth 1.5`): `Star`, а не
  `StarSolid`; `ShoppingBag`, а не `ShoppingCart`. Проверять не глазом, а разметкой — залитая
  иконка содержит `fill="currentColor"`:
  `node -e` с `renderToStaticMarkup(React.createElement(Icons.ShoppingBag))`. Ядровые пункты
  («Товары» с `Tag`, «Акции» с `ReceiptPercent`) не подменяем — это иконки Medusa.
- **Подвал и пустое состояние списка** (T4.13): подписи пагинации `DataTable`
  берёт НЕ из i18n ядра — свои строки передаём сами (`common.pagination.*`,
  формулировки совпадают с ядровыми: «результатов», «страниц», «Назад»,
  «Далее»), иначе в русской панели «1 of 1 pages». Пустой список всегда
  объясняет себя: `emptyState.empty` — «совсем пусто», `emptyState.filtered` —
  «под фильтры ничего не подошло». Свои чипы `DataTable` не видит (различает
  только собственный поиск), поэтому при активном чипе в `empty` подставляем
  «ничего не найдено» — эталон `routes/price-stock`.
- **Идиомы ядра** остаются в силе: списки — как стандартные страницы (`DataTable`, чипы фильтров,
  статус точкой в строке и `StatusBadge` в шапке карточки), действия — «…»-меню, ноль технических
  id / JSON / metadata на экране. Эталон списка — `routes/companies/page.tsx`.
- **Таблица с правкой в клетке** (эталон — `routes/price-stock`, T10.14b): `table-layout: fixed`
  ТУТ не годится — ядровый `DataTable` делает чекбокс и первую колонку данных sticky, и при fixed
  их клетка получается шире слота и накрывает начало соседней колонки. Раскладку оставляем
  авторастяжной, а колонку с длинным текстом держим ограничением ширины (nowrap + ellipsis); клетке
  с полем ввода задаём свой `min-width` — ядровый reset ставит полям `min-width: 0`, и на узком
  экране автораскладка давит поле в щель вместо горизонтальной прокрутки.
- **Загрузка файла** (эталон — `routes/price-stock`, T10.14c): своя кнопка + скрытое
  `<input type="file">` (`style={{ display: "none" }}` — произвольных утилит Tailwind в собранном
  CSS дашборда нет), и после выбора файла поле сбрасывается (`event.target.value = ""`), иначе
  повторный выбор ТОГО ЖЕ файла событие не даёт, а продавец правит его и грузит снова. Содержимое
  уходит на сервер base64 в JSON — multipart ради одного экрана не заводим. Drawer со сверкой чисел
  шире ядрового: `div.sm-*` (селектор с элементом — ядровый CSS drawer'а идёт в бандле позже нашего).

## Подписи разделов

`defineRouteConfig({ label })` вычисляется вне React, штатный `useTranslation` там недоступен.
Подписи берём через `lib/route-label.ts` (локаль — общая, `lib/locale.ts`). Смена языка в профиле
применяется к сайдбару после перезагрузки страницы. Порядок пунктов admin-SDK не отдаёт — его
задаёт слой `styles/shell.css` (T4.1a); счётчики-бейджи по-прежнему за ядром
(см. DECISIONS 2026-08-04).

## Скриншоты для гейта U

```
cd backend
npm run dev                       # стенд должен быть поднят
node scripts/admin-screenshots.mjs --spec scripts/shots/t4-1.mjs --out ../docs/qa/screens/T4.1

# кадры в режиме продавца — тем же скриптом, но его учёткой:
node scripts/admin-screenshots.mjs --spec scripts/shots/t4-1a-seller.mjs \
  --email seller@stroymarket.kz --password seller123456 --out ../docs/qa/screens/T4.1a
```

Скрипт сам логинится в `/app` (креды — `ADMIN_EMAIL`/`ADMIN_PASSWORD` или флаги `--email`/`--password`),
переключает язык и тему и снимает кадры. В спеке кадра можно задать `viewport`, `block` (заглушить
запрос → кадр ошибки), `pause` (удержать запрос в pending → кадр загрузки) и `actions`.

Действия кадра: `click` (селектор, синтетический клик), **`clickAt`** (клик настоящей мышью через
CDP `Input.dispatchMouseEvent` — нужен для строк ядрового `DataTable`: до его обработчика
синтетический `el.click()` не доходит), `waitFor`, `scrollTo`, `evaluate`, `wait`.
