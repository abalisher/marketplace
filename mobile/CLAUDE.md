# mobile/ — Flutter Pub Workspace (Dart 3.6+)

> Скаффолд ещё не выполнен (см. docs/STATE.md). Этот файл — правила, которые действуют после него.

## Структура
- `apps/buyer` — покупатель: каталог, корзина, заказы, бонусы, ИИ-расчёт, трекинг доставки.
- `apps/partner` — продавец и склад: остатки, заявки, цены; экраны показываются по роли сотрудника.
- `apps/driver` — водитель: рейсы, GPS в фоне, фото/подпись отгрузки, чек-лист возврата.
- `packages/api_client` — СГЕНЕРИРОВАН из contracts/openapi.json. Руками не редактировать. Не читать при работе — только использовать.
- `packages/core` — auth, конфиг, роутинг, push, хранилище сессии.
- `packages/ui_kit` — дизайн-система: токены (цвета/типографика/отступы) и компоненты. Все приложения строятся ТОЛЬКО из ui_kit.

## Конвенции
- Внутри приложения — feature-first: `lib/features/<feature>/{screens,widgets,providers}`.
- State management: Riverpod (генераторный синтаксис). Никакой логики в виджетах — только в провайдерах/сервисах.
- Бизнес-правила НЕ реализуются на клиенте — всё считает бэкенд, клиент отображает.
- Один файл = один виджет/экран/провайдер. Без barrel-файлов.
- Тексты — через локализацию с первого экрана: ru (основной) + kz.

## Работа с API
Только через `packages/api_client`. Нужен новый эндпоинт → задача бэкенду (фиксируй в docs/STATE.md),
НЕ ходи читать TypeScript-код — смотри contracts/openapi.json.

## Верификация итерации
`dart format --set-exit-if-changed .` → `flutter analyze` → тесты пакета/приложения → сборка затронутого приложения.
