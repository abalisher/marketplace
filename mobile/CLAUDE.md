# mobile/ — Flutter Pub Workspace (Dart 3.6+)

> Скаффолд выполнен: пустые приложения (`--empty`, платформы android/ios/web, org `kz.marketplace`)
> и пакеты-заготовки собраны в Pub Workspace (корневой `pubspec.yaml`, единый `pubspec.lock`).
> Команды pub/analyze запускаются из корня `mobile/`.

## Структура
- `apps/buyer` — покупатель: чат-ассистент и кабинет (заказы, корзина, документы, профиль),
  каталог, бонусы, ИИ-расчёт, трекинг доставки. Кабинет (T10.6c) — `features/cabinet`:
  оболочка `CabinetScaffold` (та же панель истории диалогов, что в чате, + ряд чипов
  разделов), маршруты `/cabinet/*`, старые `/orders[/:id]` — редиректы. Данные берутся
  личными роутами бэкенда (`storeListMyOrderLifecycles`, `storeListMyDocuments`,
  `storeGetMyCart`), корзина в кабинете — только просмотр (правит её ассистент).
- `apps/partner` — персонал поставщика; экраны показываются по роли сотрудника:
  - **сборщик (T10.12, готов)** — `features/assembly`: вход сотрудника (актор `user`,
    `/auth/user/emailpass`, слой `staff_*` в `packages/core`) → «мои задания» своей категории →
    задание → отметки по позициям → «Собрано». Данные — admin-роуты `/admin/assembly-tasks`
    (категорию подставляет сервер из учётки). Отметки переживают потерю сети: очередь на устройстве
    + наложение на задание (`pending_mark_rules.dart`);
  - продавец — товары, цены, заявки; кладовщик — остатки, сборка;
  - водитель — рейсы, GPS в фоне, фото/подпись отгрузки, чек-лист возврата
    (водитель — сотрудник поставщика, развозит его товар; отдельного driver-приложения нет — см. DECISIONS 2026-07-21).
- `packages/api_client` — СГЕНЕРИРОВАН из contracts/openapi.json. Руками не редактировать. Не читать при работе — только использовать.
- `packages/core` — auth, конфиг, роутинг, push, хранилище сессии.
- `packages/ui_kit` — дизайн-система: токены (цвета/типографика/отступы) и компоненты. Все приложения строятся ТОЛЬКО из ui_kit.

## Конвенции
- Внутри приложения — feature-first: `lib/features/<feature>/{screens,widgets,providers}`.
- State management: Riverpod (генераторный синтаксис). Никакой логики в виджетах — только в провайдерах/сервисах.
- Бизнес-правила НЕ реализуются на клиенте — всё считает бэкенд, клиент отображает.
- Один файл = один виджет/экран/провайдер. Без barrel-файлов.
- Тексты — через локализацию с первого экрана: ru (основной) + kz.

## Работа с API
Только через `packages/api_client`. Нужен новый эндпоинт → задача бэкенду (фиксируй в docs/STATE.md),
НЕ ходи читать TypeScript-код — смотри contracts/openapi.json.

## Верификация итерации
`dart format --set-exit-if-changed .` → `flutter analyze` → тесты пакета/приложения → сборка затронутого приложения.
