# Модуль `payment-kaspi` — провайдер Kaspi Pay / QR

**Статус:** не начат · **Код:** `backend/src/modules/payment-kaspi/`

## Назначение
Реализация Payment Provider API Medusa для Kaspi Pay / Kaspi QR. Другие эквайеры в будущем
подключаются как параллельные провайдеры за тем же платёжным шлюзом ядра — архитектура этого требует (ТЗ 3.2).

## Сценарии оплаты (сам шлюз, не только Kaspi)
- 100% предоплата · частичная предоплата (настраиваемый %) · постоплата/отсрочка (только юрлица, в лимите `scoring`).
- Частичная оплата бонусами (`bonus`) — уменьшает сумму к оплате «живыми деньгами».
- Пересчёт при частичном исполнении заказа: возврат/зачёт разницы по предоплате.
- Возврат средств при возврате товара — по регламенту эквайера, статус виден покупателю.

## Безопасность
Полные данные карт НЕ храним и НЕ проксируем — PCI DSS остаётся на стороне Kaspi/эквайера.
Все платёжные события логируются.

## Риски
Публичной песочницы Kaspi нет: строим адаптер + мок-провайдер для разработки и тестов;
реальные мерчант-ключи запросить у клиента заранее (отмечено в STATE.md → риски).

  инвойс → QR → polling статуса → webhooks → refund, SMS-авторизация мерчанта, доки ru/kz.
  ⚠ НЕОФИЦИАЛЬНЫЙ API (имитация Kaspi Pay Business) — в прод как есть НЕ брать.

  транспорт заменить на официальный при получении договора эквайринга.
