# Модуль `estimator` — ИИ-расчёт материалов

**Статус:** не начат (отдельный этап после базового MVP) · **Код:** `backend/src/modules/estimator/`

## Назначение
Помогает покупателю определить состав и объём черновых материалов: распознавание файлов проекта,
расчёт по нормативной базе, подборка в трёх сегментах, голосовой ввод (ru/kz).

## Модели (план)
- `MaterialNorm` — нормативная база расхода (материал на м²/м³ по видам работ). АДМИНИСТРИРУЕМЫЙ справочник — не хардкод.
- `Estimate` — расчёт: источник (файл/ручной ввод/голос), распознанные параметры, статус.
- `EstimateLine` — позиция расчёта: материал, количество, сегмент, привязка к SKU каталога.

## Бизнес-правила (из ТЗ 7)
- Входные форматы: PDF, DOC/DOCX, XLS/XLSX, JPEG/PNG (сканы, фото от руки). Нечитаемый файл → понятная ошибка + ручной ввод.
- Результат ЯВНО помечен как рекомендательный; покупатель может править позиции и количества.
- Подборка в 3 вариантах (эконом/комфорт/бизнес) с итоговой суммой; сегменты можно смешивать.
- Учитывает остатки: товара нет → не предлагается либо заменяется альтернативой.
- Голосовой ввод: минимум русский и казахский; STT → структурированный запрос.

## Реализация (решение в DECISIONS.md от 2026-07-10)
Внешние API: Claude API — распознавание смет/чертежей/параметров из файлов; внешний STT с поддержкой kk-KZ.
Своё ML не обучаем; при необходимости в Фазе 2 — отдельный Python-сервис за тем же API модуля.

## Упрощённый первый шаг (рекомендация ТЗ)
Сначала расчёт по вручную введённым параметрам (площадь/периметр/высота) без распознавания файлов;
распознавание файлов — вторым шагом.
