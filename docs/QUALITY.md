# Контроль качества (гейты)

> Правило: таск в `docs/PLAN.md` считается закрытым (`[x]`) ТОЛЬКО после прохождения всех назначенных
> ему гейтов. Результат фиксируется короткой строкой прямо в таске: `Гейты: К✅ U✅ Ф✅ (отчёт docs/qa/...)`.
> Гейт провален → таск остаётся `[~]`, по замечаниям заводятся фикс-подзадачи там же.

Назначение гейтов по типу таска (указано в паспорте каждого таска в PLAN.md):

| Тип таска | К (код) | U (UI/UX) | Ф (фокус-группа) | В (владелец) |
|---|---|---|---|---|
| Backend без UI | ✅ | — | — | — |
| Экран / компонент UI | ✅ | ✅ | — | — |
| Пользовательский флоу (экран в сквозном пути) | ✅ | ✅ | ✅ | только ключевые |
| Приёмка эпика / релиза | ✅ | — | ✅ | ✅ |

## Гейт К — качество кода (каждый таск)

- **Backend:** `eslint` 0, `tsc` 0 (оба tsconfig), unit + integration затронутой части зелёные,
  dev-сервер поднимается и затронутый эндпоинт отвечает (live-smoke). Изменён API → регенерация
  `contracts/openapi.json` + Dart `api_client` в том же таске или явным следующим таском.
- **Storefront:** `next lint` 0, tsc затронутых файлов 0, `prettier` чист, `npm run build` проходит.
- **Mobile:** `dart format --set-exit-if-changed .` чист, `flutter analyze` 0, тесты затронутых
  пакетов зелёные, `flutter build web` затронутого приложения проходит.
- **Общее:** изоляция «один таск = один модуль/пакет», правила `CLAUDE.md`. Для нетривиальных тасков
  (новый экран, новый workflow, изменение денег/статусов) — ревью вторым агентом (`/code-review`);
  замечания устранены или явно отклонены с причиной.

## Гейт U — качество UI/UX (таски с экранами)

Чек-лист (все пункты):
1. **Сверка с эталоном:** покупательские чат-экраны (buyer + витрина) — по брифу
   `docs/qa/2026-08-27-T10.1-gemini-brief.md` (эталон вида — Gemini, решение владельца 2026-08-25;
   макет «Ассистент» больше не эталон для них); остальные — по standalone-HTML в корне репо
   («Курьер» / «Продавец»). Проверяем раскладку, отступы (4/8/12/16/24/32), типошкалу, радиусы,
   цвета — только токены дизайн-системы. Проверять в СВЕТЛОЙ и ТЁМНОЙ теме.
2. **Все состояния экрана:** loading / пусто / ошибка (+«Повторить») / успех.
3. **Локали:** ru и kk (витрина — ещё en); тексты не обрезаются и не вылезают за границы.
4. **Эргономика:** тап-таргеты ≥48dp, деньги tabular-цифрами с единицей измерения, номера
   человекочитаемые, ноль технических id / JSON / metadata на экране.
5. **Только дизайн-система:** компоненты/токены `ui_kit` (mobile) или зеркальные токены (web);
   никаких ad-hoc цветов, размеров, шрифтов.

Артефакт: скриншоты (свет+тьма, ключевые состояния) в `docs/qa/screens/<таск>/` + 3–5 строк резюме.

## Гейт Ф — фокус-группа (пользовательские флоу)

Механика ИИ-прогона:
1. Поднимается живой стенд (backend + сборка клиента; для чата допустим прогон через API).
2. Персона-агент получает ТОЛЬКО легенду персоны и жизненную задачу («обшей комнату 4×3,5
   гипсокартоном — посчитай и закажи») — БЕЗ знания интерфейса и без подсказок по шагам.
   Задача берётся из ЖИВОГО ассортимента (четыре категории, T10.10): легенды про фундамент,
   кровлю и общестрой недействительны — этих товаров магазин не продаёт.
3. Персона проходит сценарий: чат — диалогом через API/UI; экраны — web-сборка + headless-браузер,
   либо пошаговые скриншоты с решением «куда нажать» на каждом шаге.
4. Отчёт в `docs/qa/<дата>-<таск>-focus.md`:
   - выполнена ли задача без подсказок;
   - каждый затык (не понял / ошибся / лишние шаги) с оценкой: **блокер / мешает / косметика**;
   - субъективная оценка удобства 1–5 и вердикт «что бы сказал живой прораб».

**Критерий прохождения:** задача выполнима без подсказок и 0 блокеров. «Мешает» → фикс-таски
в PLAN.md (закрыть до конца эпика). «Косметика» → по усмотрению владельца.

## Гейт В — приёмка владельцем (ключевые экраны)

Ручная проверка Алишером до закрытия таска. Список ключевых экранов:
- чат-подбор с карточками товаров (buyer);
- оплата Kaspi QR в чате;
- деталь заказа / трекинг с кодом получения;
- очередь заказов продавца (принять → собрать → передать);
- «взять заказ» и выдача на точке у водителя;
- финальная приёмка релиза (T9.3).

Формат: агент готовит стенд + короткий чек-лист «что проверить руками», владелец отвечает
ОК / замечания. Замечания → фикс-таски в PLAN.md.
